# I2: keep board selection visible

PRE catalog containment: `sol_41e954f7b51b4cb0` unsat/fail for a two-row selection at y=39 in an inner 88×6 viewport at (1,1); `sol_7710b9e8eacd492b` sat/pass after moving it to y=5. This declared twenty-task witness shows the required residual height, not runtime behavior.

RED: remote `scripts/spur-cargo test -p spur-tui --test plan_inspector_board -- --nocapture` exited 101, 2 passed/2 failed: selected row outside lane and selected row outside stacked viewport. The first selected row was visible; middle/last selections failed. Test commit `f17c60e66`.

Fix derives a fresh offset from selected start/end rows and actual inner viewport height, including metadata, headings, separators and borders. It skips source rows without a u16 scroll cap. When a selection is taller than the viewport, its title has priority. There is no separate persisted board offset to become stale after resize or navigation.

GREEN: remote board + existing snapshot targets, 23 passed (4 + 19), exit 0. Twelve observed selected-row positions cover first/middle/last at heights 8 and 5 in both modes. Wide fixtures include retry metadata for every task; stacked fixtures retain the selected stage heading.
