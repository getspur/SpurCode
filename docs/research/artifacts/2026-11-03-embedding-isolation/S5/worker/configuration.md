# Provisional graph helper configuration

Until the packaging task supplies companion discovery and grounded policy, the embedding-enabled graph needs `SPUR_EMBEDDING_HELPER_CONFIG` containing a JSON object and `SPUR_ORT_CACHE` naming a writable, isolated runtime cache. The companion is built separately; graph never compiles or downloads an executable at runtime. `SPUR_MODEL_CACHE` may select the model cache; otherwise the worker uses its normal user cache. Nomic and Jina cold-cache acquisition and CodeRank's pinned-revision acquisition belong to the helper.

Every JSON field is required. `executable` is the companion program path and `args` is its argument-prefix array. `artifact_budget` is the maximum verified total artifact bytes. `limits` contains numeric `max_frame_bytes`, `max_texts`, `max_text_bytes`, `max_total_text_bytes`, `max_dimensions`, `max_identity_bytes`, and `max_pending`. The remaining numeric fields are `queue_capacity`, `max_restarts`, `startup_timeout_ms`, `request_timeout_ms`, `shutdown_timeout_ms`, and `shutdown_poll_interval_ms`. The protocol/client validate these values, reject zero capacity or timeout and arithmetic overflow, and reject requests exceeding the selected bounds. The graph enforces the existing 768 dimensions and model selection, formatting and stored vector identities.

Choose bounds that accommodate the graph's configured batch size and the actual formatted text lengths. No measured acceptance number in the research artifacts is a shipping default or an RSS guarantee. Missing or invalid configuration makes embedding unavailable with a warning; there is no in-process fallback. The existing skip flags do not launch a helper. Review S7 must provide a deployment configuration and companion path before default distributed embedding is considered complete.
