`verify.py` reads only frozen artifacts using the Python DuckDB reader; it independently checks stored vectors, formatted inputs, source fields, process events, feature/dependency trees and the reference comparisons. It emits actual observation-derived `post-candidates.json`. Its first version used PyArrow, which could not read a nullable fixed-size vector list (`ArrowInvalid: Expected all lists to be of size=768`); the read-only verifier was changed to DuckDB and rerun successfully without changing the artifacts. This evidence reader is not a helper dependency. `independent-policy.json` states the desired policy separately and `adversaries.json` gives exact candidate corruptions; they are not solver outputs. Root must compile and execute fresh Jev POST, inspect domains and persist/reload actual receipts. `post-interpretation-note.md` explains why the prospective graph `database_deps` value needs interpretation against observed Parquet storage rather than being copied.
