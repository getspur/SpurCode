### Existing canonical collectors

`rust_declarations.rs:91` publicly exposes `RustDeclarationEvidenceSet` v2: schema/extractor/graph hash, scope, covered kinds, sources, tuple `rows`, `foreign_functions`, `extern_blocks`. `RustDeclarationFile` retains path, file ID, source OID, byte length and `Complete { row_count }` or `Unknown { reason }`. Each tuple retains its symbol ID, structural and lexical owner, physical ordinal, full/type/line ranges, raw visibility and attributes. `collect_rust_declarations:118` checks the current manifest version, full manifest hash, physical files and exact blob bytes. Its `validate:105` compares the entire set to source recollection. Recovery/invalid UTF-8 produces Unknown while independent intact declarations can remain. Raw cfg attributes do not make this physical declaration collector evaluate cfg.

`rust_declarations/ffi.rs:8–64` provides `RustDeclarationAbiSyntax::{Omitted, Explicit { literal }, Inherited { extern_block_id }}`, `RustDeclarationBody::{AbsentForeignDeclaration, NonExecutableContainer}` and typed function/block rows. Each retains names, both owners, full/core byte and line ranges, qualifiers, visibility, attributes, raw ABI and body category. Function signatures have no local executable body; extern blocks are structural, lexically transparent containers. These rows must remain lossless, including raw ABI literal spelling and attribute ranges. No ABI resolution, linkage, callee or execution claim follows.

`panic_evidence/call_sites.rs:37,53,65,76` provides `RustBodyEvidence`, `RustCallSiteEvidence`, `RustCallSourceBinding` and `RustCallSiteEvidenceSet` v1. Bodies retain kind/range, source/path and optional exact definition symbol. Sites retain text/range, source/path, site ID and innermost body ID. Sources retain exact file identity, byte length and body/site counts. `collect_rust_call_sites:107` calls `collect_method_call_sites` for source authentication, then rejects parse recovery and unevaluated cfg/cfg_attr; macro token trees are opaque. `validate:89` rejects omissions, duplicates, reordering and wrong existing same-file bodies by complete recollection. `snapshot_id:393` hashes domain, path, **source OID**, range and kind; it does not hash the whole graph. The set's graph hash still identifies its original collection snapshot. Both identity facts matter.

## Chosen contract and validation boundary

The plan specifies one `Option<RustEvidenceSet>` field named `rust_evidence`, outer schema `spur-rust-evidence-v1`. It wraps, rather than replaces, original declaration v2 and call v1 sets. Every eligible physical Rust manifest has exactly one per-file entry. Captured empty workspace is `Some` with no files; legacy absence is `None`. A healthy zero-declaration/zero-site source retains a source row. Non-Rust, virtual notebook cells and `external://` placeholders do not become supported physical sources.

Per-file declarations retain their canonical Unknown state and any intact rows. Calls are independently `Complete { evidence }` or `Unknown { reason }`, with finite reasons invalid UTF-8, recovered syntax, unevaluated cfg or parser unavailable. The wrapper authenticates file identities/OIDs first, classifies only those syntax conditions, and invokes R3 separately on each healthy file. Any other collector error propagates; a stale owner or manifest cannot be hidden as Unknown. It never catches every error and emits an empty complete set.

Original snapshot inventories are deduplicated in `origins`: each stores the collection graph hash, manifest version and the exact sorted path/file-ID/OID inventory that recomputes that hash. Per-file nested sets keep their original headers. Composition unions needed origins, drops unreferenced origins and replaces/removes complete file entries. An origin inventory may mention a file subsequently deleted; that historical provenance is distinct from active source coverage. No old body/site ID or nested snapshot header is relabeled with the new aggregate hash.

For canonical recollection, construct an **origin view** from the current authoritative graph's files/symbols for the unchanged source, original manifest inventory and original graph hash. Precheck that the current selected file's ID/OID equals its original binding; call the existing public collectors/validators on that view and one exact source. Neither existing collector nor its identity algorithm needs weakening. A forged graph hash inconsistent with the retained origin inventory rejects. Provenance is still a self-contained recorded snapshot, not a cryptographic attestation by an external producer.

Three boundaries are explicit:

1. `validate_stored(graph)` checks versions, canonical ordering, origin/hash/source agreement, exact coverage, IDs, ranges/counts, unique keys, source/body/site FKs and actual graph owners. It cannot authenticate unseen source text or discover omitted canonical syntax.
2. `validate_sources(graph, sources)` first requires the exact physical source domain and bytes, then recollects both lanes through origin views and compares every field. Wrong existing owners/bodies, same-count swaps and omitted healthy zero sources reject here; matching checksums alone cannot prove canonical syntax.
3. Disk/query decoding checks all five core tables, strict columns/metadata/counts/checksum and stored structure **before filtering**. Canonical artifact hashing includes the optional envelope; absent remains omitted. A source-only graph hash does not authenticate table bytes. A filtered result is a projection, not a complete artifact suitable for canonical validation or cache publication.

Incompatible declared Rust disk schemas/extractors fail with an actionable `spur explore sync` rebuild message. Recognized old artifacts lacking this capability remain usable with evidence unavailable. Full/slim current readers retain the new envelope; slim retains its own source bindings even after clearing general manifests. History-only projections expose `None` and cannot be reused as current evidence seeds. No change to existing temporal ID rewriting is authorized.
